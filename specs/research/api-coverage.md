## 核对范围与结论

信息需求来自项目内 [企业公开线索分析心智](../analysis/skill.md)，以及本机 `company-cross-analysis` Skill 的主体校验、业务、资金、控制关系和风险交叉分析矩阵。

本轮核对天眼查官方 MCP 工具目录与企查查官方开放平台。以下“有接口”只表示官方文档存在对应产品，不表示当前账号获授权、目标企业有数据、返回最新完整、可以无限分页，或应用已接入。MCP 工具通过已有服务端接口调用，属于可程序获取的能力，但不等于任何人都能免费调用。

| 标记 | 本文含义 |
| --- | --- |
| 有接口 | 已找到对应的商业数据产品；仍需账号权限与响应样例验收 |
| 条件覆盖 | 有接口能提供一部分公开线索，不能直接取得该命题所需的完整事实 |
| 未确认通用接口 | 本轮未核实到能普遍覆盖中国非上市公司的授权公开标准 API；不宣称所有行业/地方均无接口 |

基本登记与风险记录的 API 覆盖比较明确；经营真实性、真实产能、交易完成、回款与偿付能力仍需跨材料判断。

## 访问门槛：哪些有API，但不能直接随便查

下面的访问限制与后文“API覆盖”是两件事。本文列出的商业接口不能仅凭公开接口地址匿名使用；至少需要对应凭据、工具/接口开通与有效权益或额度。免费试用也不表示无需申请、实名或场景审核。

| 标记 | 准确含义 | 不应误解为 |
| --- | --- | --- |
| 凭据/开通 | 需要服务商签发的Key、对应接口或工具使用权 | 知道接口名就能调用；注册成功就获得全部工具 |
| 实名+场景审核 | 已核实的企查查产品明确要求申请方为企业实名用户，并提交应用场景审核 | 个人网页会员自动有API权限；只要充值一定获批 |
| 权益不足（实测） | 提供方原始错误明确说明当前Key缺少特定工具权益 | 目标企业无该类记录；接口尚未实现；一定是额度用尽 |
| 额度/频率 | 即使已经开通，仍受调用次数、余额或频率限制 | 开通后可无限查、无限分页、随意存储和转售 |
| 披露范围限制 | 授权充分时也只能取得已覆盖的企业、字段和期间 | 加钱即可取得未公开的财务、全量客户或实时现金 |
| 门槛待核 | 有产品目录，但本轮未逐项核实该SKU的场景审核、套餐、申请主体等细则 | 无限制、个人可直接调用 |

### 当前天眼查报错：权限不足还是额度用尽

2026-10-24，使用本项目服务端Key对 `get_shareholder_info` 做一次最小复查，返回：

```text
HTTP 403
error: insufficient_entitlement
message: 工具 get_shareholder_info 需要 VIP 权益，请升级后重试
```

**这次阻断的直接原因是该Key缺少股东工具的VIP权益，原始响应没有说额度已用完。**本轮没有读取账户余额或剩余次数，因此不判断账号剩余额度，也不保证权益开通后就不会遇到另一个额度限制。升级哪种产品、网页会员是否覆盖MCP/接口权益，需要在天眼查侧确认，不能由“VIP”三个字推断。

| 取得的证据 | 可以判断什么 | 恢复方向 |
| --- | --- | --- |
| 403且原始error为`insufficient_entitlement`，正文说明VIP权益 | 对应工具权益不足 | 核对Key绑定账号及MCP/接口工具权益，必要时申请/升级 |
| 仅看到应用的`UPSTREAM_AUTH` | 只知道适配器归类为鉴权/权限问题，不能单凭它判断具体原因 | 查脱敏后的原始错误码和说明；当前代码把401/403归为同一个应用码 |
| 仅HTTP429 | 可能涉及限流或额度，需要原始错误进一步区分 | 不能一概说“充值”或“一定没权限” |
| 官方文档说明“有接口”，但本Key没测试 | 只能确定产品存在 | 标记待验证，不能预先写成成功或失败 |

本段只保存工具名、状态和脱敏错误说明，不保存或展示Key；没有为排查而批量重复调用全部14个工具。

### 建议的接入优先顺序

1. 主体、登记/股东、年报：先把资本、出资、人员和经营范围的基本口径做清楚。
2. 异常、处罚、执行/失信/限高、裁判/开庭、冻结/抵押：完成风险线索与历史状态核对。
3. 许可/资质、招投标、专利：为业务真实性提供不同形成机制的公开痕迹。
4. 客户/供应商、融资、财务：先选目标行业与样本试验覆盖，再决定投入，避免买到大量空返回。

这些是选型建议，不是已修改的查询计划。需要向供应商核对开通主体、场景审核、字段、分页、历史期间、详情/原文定位、按次收费、空返回计费、缓存和展示授权。本轮未提供未经核验的套餐成本测算。
