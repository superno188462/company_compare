## 1. 用户任务与信息架构

核心任务：搜索企业 → 确认主体 → 查看资料取得情况 → 阅读证据与有限报告 → 浏览官网 → 手工补充 → 自动刷新分析。

采用一个工作台，包含搜索态、候选态和结果态。官网在独立标签页打开；不增加应用内 WebView 页面。手工录入在结果态内展开，不另开聊天页。UI 文案统一由后续 `text-dict.json` 管理，本稿文字为待评审文案。

## 3. 页面与组件边界

| 组件 | 职责与必要内容 | PRD 关联 |
| --- | --- | --- |
| 顶栏与官网入口 | 产品名、固定官网选择入口、外部打开与失败提示 | REQ-13 |
| 搜索栏 | 公司名称、合法性反馈、提交状态；不接受自由分析提问 | REQ-01、04 |
| 候选列表 | 候选主体字段、缺项、独立确认按钮、当前搜索结果来源 | REQ-04 |
| 主体栏 | 当前企业全称/代码、其他已知标识；切换主体需处理未提交草稿 | REQ-04、12 |
| 查询覆盖面板 | 按类别展示有数据/无返回/失败/未查询，显示计划覆盖 | REQ-05 |
| 全局提示区 | 渲染后端提示项，区分信息不足、部分失败、未核实等 | REQ-12、14 |
| 证据列表 | 稳定证据编号、内容、来源、日期、链接、衍生关系说明 | REQ-09 |
| 报告区 | 完整原文、对应证据版本、状态、旧版提醒和重试 | REQ-07、11、12 |
| 线索表单 | 明确主体归属、文本及来源字段、自愿共享、错误与提交反馈 | REQ-08、10 |
| 快照确认区 | 他人快照出处与时间、预填充样式、知情确认、修改/清空 | REQ-06 |

同一主体、证据版本和报告状态各自保持一个可信来源，不从卡片内容反推状态。前端不擅自更改来源类别或将相同内容解释为多份独立证据。

## 4. 工作台状态与转换

| UI 状态 | 展示内容与可用操作 | 事件后的行为 |
| --- | --- | --- |
| 初始 | 搜索栏、主体/信息局限提醒、官网入口 | 搜索合法名称后进入搜索中 |
| 搜索中 | 保留查询词、加载反馈；禁用重复搜索提交 | 返回候选/空态/搜索失败；不自动确认主体 |
| 零候选 | 本次未返回匹配企业、修改名称入口 | 再次提交搜索 |
| 候选待确认 | 主体卡片；有代码才可确认 | 点击确认后进入详情取得中 |
| 搜索失败 | 可识别失败提示、保留查询词、重试 | 重试同次操作，不清空已有工作台结果 |
| 详情取得中 | 已确认主体、取得进度、官网入口 | 完成后显示覆盖与证据，再按条件生成或进入材料不足 |
| 部分成功 | 已有证据、缺口提示、失败类别重试 | 有有效证据则自动有限分析；不自动预填充共享快照 |
| 无详情但有快照 | 他人快照预填充表单、确认框、时间和来源 | 未确认不分析；确认合法提交后接纳并分析 |
| 材料不足 | 主体、覆盖情况、补充线索入口；报告区说明不足 | 有效手工录入后自动分析 |
| 生成中 | 当前证据版本、生成状态；旧报告可保留但标为旧版 | 接收对应版本的完整结果，不渲染正式半段报告 |
| 分析成功 | 完整报告、来源引用和证据版本 | 用户补充线索后生成新版本 |
| 分析失败 | 证据仍在、生成失败及当前版本重试 | 仅重试当前分析，不重复添加线索 |
| 归属待修正 | 保留草稿、代码缺失/不匹配或冲突说明 | 修改后再校验；不追加证据、共享或调用 LLM |
| 会话已结束 | 明确过期/重置提示；不展示其他会话数据 | 重新开始搜索 |

不存在“查询失败即零风险”或“没有线索即企业安全”的视觉状态。

## 5. 手工录入与快照确认

### UI-03 自行录入

- 先展示当前主体；“来源记录信用代码”要求用户核对填写，不自动把当前代码伪装为来自原始记录的值。
- 线索正文和归属代码必填；本会话使用可以缺链接/查看时间，但显示未提供出处/时间。选中共享后，链接和查看时间变成必填，并明确说明共享仍不代表已核实。
- 匹配性、格式和时间问题就近显示；失败保留内容，不清空已填表单。
- 可保存待修改草稿。草稿不是证据；不匹配时只允许保存草稿/修改，不执行正常提交。
- 自愿共享默认关闭，不以继续使用应用为由强制共享。

### UI-04 他人快照预填充

- 原始预填充值以可读的浅色背景/辅助色和斜体标识，配“来自他人快照”文字标签；不能仅用颜色区分。
- 展示该快照的原始查看时间、共享时间、来源链接和未核验说明。不得将当前时间代填为用户已访问官网的时间。
- 增加必选知情框：“我知道这些内容由其他用户提供，可能过时，系统未核验原网页；我已核对其主体归属，并同意用于本次分析。”
- 知情框默认不勾选；未选中时提交按钮不可用且说明原因。服务端必须执行同样规则。
- 接受快照与自愿共享是两件事，不互相勾选。接受原文不改变其 `user_other` 来源；修改后的内容保留衍生标识。
- 清空快照后改为自行录入，恢复自行录入规则；取消勾选不隐式提交。

### UI-05 提交反馈

提交时禁用重复点击并显示保存状态。会话保存、共享、报告生成的结果分别提示：例如“线索已保存；报告更新失败，可重试”，不能用单一“提交失败”掩盖已保存的事实。

报告生成过程中可编辑下一条草稿；提交按钮需等待当前提交完成。修改草稿不自动触发 LLM，只有合法提交才触发。

共享成功显示回执与“撤回共享”操作，说明仅影响后续共享预填充，不承诺撤回已被其他会话接纳的副本。没有当前提交者权限不显示可执行撤回操作，后端仍需验证。

## 6. 来源样式与视觉方向

整体为中文资料工作台：浅色背景、中性正文、清晰层级、适中信息密度。优先可读性与出处识别，避免警报式金融营销视觉。

| 来源 | 建议视觉 | 必须同时出现的文字 |
| --- | --- | --- |
| `tianyan` | 蓝色边框/标签 | 天眼查聚合资料；系统未核验官方原文 |
| `user_other` | 琥珀色边框/标签 | 其他用户提供；系统未核实 |
| `user_self` | 青色边框/标签 | 本次用户录入；系统未核实 |

颜色代表来源渠道，不表达风险等级。错误仅用于操作/接口失败，警告用于覆盖不足/未核实，不给整家公司加红绿灯。

报告保留模型生成原文语义和段落；可安全渲染文本/有限 Markdown，但不执行模型 HTML、脚本或工具指令。引用链接和证据定位是导航，不代表系统已经读取链接。

## 7. 刷新、导航与并发

### UI-06 切换企业

已存在未提交草稿时，确认新主体前弹出说明：“切换后将清除当前未提交草稿。”用户取消则保留当前主体和草稿。开始搜索并不立即替换已确认主体；确认切换才建立新的当前主体上下文。

### UI-07 刷新与返回

同一有效会话刷新或从官网标签页返回时，恢复主体、已保存证据、报告版本和当前草稿；会话已结束则明确提示重新开始。恢复状态不能跨用户/会话混用，客户端不保存服务端密钥和接口令牌。

### UI-08 迟到响应与等待

只有匹配当前主体和证据版本的结果可更新当前报告。旧结果晚到时不覆盖新结果；上一版报告需要显著写明对应版本。停止等待只改变界面等待状态，后台操作是否完成按实际状态恢复展示。

查询失败类别可重试；重试后如果证据发生变化，更新版本并自动分析。单纯查看官网、编辑草稿、展开卡片不发起 LLM 调用。

## 8. 响应式与可访问性

- 桌面结果态使用证据/报告双列；窄屏改为单列，顺序为主体、覆盖、提示、报告、证据、录入。
- 官网入口在窄屏仍常驻可用，但不遮挡表单；无弹窗支持时提供可复制地址。
- 表单、候选确认、知情框、重试等均支持键盘操作；字段有明确标签，加载/失败反馈可被辅助技术识别。
- 预填充文字保持可读对比度；来源、失败、未核实均有文字，不单靠颜色或斜体。
- 不自动切换焦点到旧报告；错误时定位到相关字段，用户输入不会无提示丢失。

## 9. 页面操作与能力映射

本表仅列能力边界，不提前锁定 URL、函数签名和 JSON 字段。

| 用户操作/状态 | 所需应用能力 | 领域资源 |
| --- | --- | --- |
| 搜索企业 | 查询候选列表 | 搜索结果、候选主体 |
| 确认主体 | 校验候选并开始受控资料查询 | 会话、已确认主体、查询覆盖 |
| 重试失败类别 | 重试对应资料取得并更新当前版本 | 分类查询状态、证据版本 |
| 展示他人快照 | 在整体 empty 条件下取得可用草稿 | 共享快照、当前主体 |
| 保存待修改录入 | 保存会话草稿，不运行分析 | 私有草稿 |
| 提交有效录入 | 校验归属、接纳证据、按同意范围共享、自动分析 | 证据、共享回执、报告版本 |
| 重新分析 | 对当前证据版本生成报告 | 报告、LLM 状态 |
| 撤回共享 | 验证提交者权限并移出后续共享查询 | 共享回执、共享状态 |
| 打开官网 | 用户主动在新标签页打开受控官方地址 | 官网入口列表；不回传网页内容 |
| 重置会话 | 清理当前私有草稿与结果 | 会话；不默认撤回已明确共享的记录 |
