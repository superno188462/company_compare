# 共享契约与数据语义

## 基线

契约版本：CONTRACT-1.0；日期：2026-10-22；状态：用户以“好先生成骨架吧”确认进入骨架阶段。关联 [PRD-1.0](prd.md)、[UI-1.0](ui_notes.md)。本文不代表骨架或测试已获批准。

权威机器定义为 `contracts/` 下的 [input-schema.json](../../contracts/input-schema.json) 与 [output-schema.json](../../contracts/output-schema.json)，采用 JSON Schema 2020-12。输出引用输入中的共享定义；只允许离线注册本项目两个文件解析 `$ref`，禁止校验器自行访问网络。

字段名、类型、必填与空值以机器定义为准；跨字段、授权、时间和状态行为以本文及前后端 SDD 为准。生成 Pydantic/TypeScript 类型时保留 description 与约束，不另维护冲突定义。

## DATA-01 主体、证据与未知

- `Subject`：必须包含企业全称、格式合法的信用代码、注册地区、法定代表人、成立日期和人工确认时间。未知的三个基础字段用 `null`，不写空字符串或臆造值。`confirmed_at` 为服务端记录，不接受客户端指定。
- `Evidence`：只有当前主体已接纳的线索可进入。`subject_credit_code` 必须等于当前主体；证据编号在本会话主体代次内唯一、不可复用。
- `snapshot_time` 表示实际取得或用户声明查看来源的时间，用户未知时可以为 `null`；`captured_at` 表示本会话接纳时间；`event_time` 是来源中的事件时间/期间原文，三者不得混用。
- `source_url` 未提供为 `null`，提供时只接受合法 HTTP(S) 绝对地址，拒绝用户信息段、控制字符、javascript/data/file 协议。不执行解析后的网页请求，也不进行 HEAD 探测。
- `source` 由服务端根据取得路径决定；用户不能自报为 `tianyan`。对应 `hint_id` 必须与来源一致。所有记录的原文核验状态均为 `original_not_verified`。
- `origin_id` 标识同源材料；衍生内容沿用该根标识，`derived_from` 指明直接来源。该来源可以不在当前证据包中，模型不得将其当成本包存在的引用。
- 同一来源记录的重试不能创建新证据；不同阶段可保留不同记录，但保留原始案号/记录 ID，不能据条数推断独立事件数量。
- 天眼查字段按规格需要规范化，排除提供方评分、风险等级和无关个人联系方式，不把这些字段交给 LLM 或前端。

## DATA-02 查询覆盖与聚合

类别固定为 `basic / abnormal / penalty / judicial / asset`。每类必须显示实际子范围 `scope_description`，不能把“只查了被执行人”描述为“已查全部司法记录”。同一类别需要多个接口时，计划开始前固定其子范围。

分类状态 `ok` 表示计划子范围、分页全部完成且取得有效记录，`empty` 表示全部成功但无记录，`error` 表示本类别未完整取得，`not_requested` 表示未纳入计划。未完整取得的类别不把部分页当作完整证据集合发布，其本轮 `record_count=0`，旧版同类别已完整取得的证据可保留并标明原时间。

聚合规则按本轮计划范围计算：全部成功且至少一类有记录为 `ok`；全部成功且全空为 `empty`；全部 `error` 为 `error`；其他组合为 `partial`。计划必须非空，未计划类别为 `not_requested`。本轮开始后不能因为权限/超时而缩小计划来制造成功。

搜索卡片不计入详情记录。手工证据不改变天眼查查询状态。旧版证据仍可用于有限分析，但其时间不重写为本次查询时间。本轮天眼查失败不会自动删除已接纳的用户线索。

## DATA-03 分析输入与完整结果

分析输入严格只有 `subject`、`evidence_list`、`api_status`。其中 `api_status` 仅为查询覆盖三字段，不包含会话凭据、共享回执、待确认快照、私人草稿、旧报告或自由提问。

无证据时不调用 LLM。输入最多 200 条证据、每条正文 4000 字符；序列化 UTF-8 输入最多 256 KiB，并且必须满足选定模型真实上下文限制。超过限制返回明确错误，不静默截断、抽样、摘要或丢弃证据。添加证据超过条数上限时拒绝添加；已经保存的数据因模型上下文限制生成失败时保留。

完整结果仅有五个顶层字段：`subject / evidence_list / summary_text / api_status / ui_hint_group`。运行元信息放入 `api_status`，不把工作流状态写进模型原文：

| 字段 | 含义 |
| --- | --- |
| `session_id` | 会话定位；不能单凭此字段授权访问 |
| `session_generation` | 本会话确认主体的代次，首次为 1，切换递增 |
| `operation_id` | 产生本次工作台状态的操作 UUID |
| `result_revision` | 同一主体代次中单调递增的结果修订号 |
| `evidence_version` | 分析输入版本；证据或查询覆盖发生实质改变时递增 |
| `summary_evidence_version` | `summary_text` 实际对应的分析输入版本；无成功报告则 null |
| `summary_generated_at` | 成功报告取得时间；无成功报告则 null |
| `llm_status` | 当前版本的分析状态，不代表旧报告状态 |
| `snapshot_status / snapshot_draft` | 共享查询情况与尚未接纳的预填充草稿 |
| `last_submission` | 当前代次最近一次已接纳提交的历史回执；无则 null。共享保存结果不代表该记录此刻仍有效，当前 active/withdrawn 状态以会话的 ShareReceipt 为准 |

语义约束：

1. `llm_status=success` 时报告非空，报告版本等于当前证据版本，且报告原文完全保持。
2. `summary_evidence_version=null` 时正文为空，生成时间为 null。
3. `error / invalid_output / running` 时可保留同主体上一版成功报告；其版本不得大于当前版本，较旧时必须包含 `REPORT_STALE`。
4. `skipped_no_evidence` 时证据为空、正文为空、报告版本和时间为 null；包含 `NO_EVIDENCE`。
5. `snapshot_status=available` 只允许天眼查整体 `empty`，草稿必须非空；其他快照状态草稿为 null。
6. 结果不得包含其他会话的私有内容、用户凭据、回执秘密或提供方密钥。

## DATA-04 共享快照与期限

仅从当前信用代码读取他人共享记录，排除当前提交者自己的共享项；若多条有效记录，按服务端共享时间倒序，再按记录 ID 排序，选择第一条预填充。排序仅选择表单初始内容，不代表内容可信度。

共享过期时间为 `min(来源查看时间, 服务端共享时间) + 7×24小时`。`now >= expires_at` 即不可再查询/接纳/共享，未来查看时间非法。预填充展示后、用户提交前需再次校验到期与撤回状态；不能靠旧页面绕过。

接纳未修改快照时保留 `user_other`，`snapshot_time` 保留原查看时间，`captured_at` 为本次接纳时间。同意使用不会把旧时间变成新时间。修改内容时可以生成 `user_self`，但保留原始根标识与来源关系，不能借改写重置原共享材料有效期。

共享需有效匹配代码、来源链接、查看时间和主动同意；对预填充还必须知情确认。未满足共享条件但请求了共享时，提交前明确拒绝并保留草稿，用户取消共享或补全后再提交。外部共享存储故障发生在会话保存之后时则保留会话证据并报告共享失败。

撤回即时停止后续查询和接纳；既有会话副本仍可用于本会话分析。禁止从已撤回/到期根记录再创建共享项。为执行该限制可保留不含正文的根记录状态至原到期时间；共享正文在到期/撤回后清理。

期限到达即禁止访问；物理清理任务最迟 5 分钟内删除到期正文。私有会话副本受会话期限单独约束，不能因共享原件到期而对其作不存在的“已验证最新”声明。

## DATA-05 会话、权限与幂等

会话从最后一次被接纳的用户交互起 24 小时后结束，`now >= expires_at` 时拒绝读取或写入。搜索、确认、保存草稿、提交、主动重试、撤回/重置及显式用户活动续期属于用户操作；后台轮询、LLM 运行、服务器定时任务和单纯自动刷新不续期。表单编辑通过限频活动通知续期，不能伪造客户端时间。

结束/重置后私有草稿、证据、报告和任务结果立即不可访问，5 分钟内物理清理。迟到任务不能恢复已结束会话。共享记录按自身期限独立保留。

浏览器由服务端签发匿名所有者凭据，用于跨刷新恢复与验证共享提交者；通过 HttpOnly、SameSite=Strict 的 Cookie 传递，正式 HTTPS 环境启用 Secure。本地 HTTP 开发例外须显式配置。凭据不得出现在模型输入、公开 ID 或响应正文。修改操作验证同源请求；首版不开放跨域 API。

各修改操作携带 UUID 幂等键。同一所有者、会话和操作类型下，同键同内容重放原操作，不重复保存/共享/调用 LLM；同键不同内容为 `IDEMPOTENCY_CONFLICT`。操作键至少保留到会话结束；共享撤回天然幂等。

会话每个主体代次同时只运行一个会改变证据/报告的任务。重复当前操作返回原句柄，其他冲突操作返回 `OPERATION_CONFLICT`。新搜索不覆盖当前主体结果；确认切换使旧代次失效，旧任务不可写回新代次。
